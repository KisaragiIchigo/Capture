# Capture

Windows 向けの画面 / ゲーム録画ソフトです。OBS Studio のキャプチャエンジンをアプリ内部に隠し持ちながら、表に出るのは録画だけに特化した高密度なプロ機材コンソール UI という構成になっています。Electron + React + TypeScript で構築しています。

## 機能ハイライト

- 🎮 **ゲームキャプチャ** — DirectX / Vulkan のグラフィックスフックを利用し、ボーダーレスウィンドウだけでなく排他フルスクリーンのゲームも録画できます。対象を指定しない場合は前面のフルスクリーンアプリケーションを自動的に捕捉します。
- 🖥 **4 種類のキャプチャモード** — フルスクリーン、指定した領域、ウィンドウ、ゲームに対応します。マルチモニタ環境では録画対象のモニタを選択できます。
- 📦 **エンジンの自動セットアップ** — キャプチャーエンジンはインストーラへ同梱されます。初回起動時に、書き込みできる場所へ自動で配置するだけで完了するため、ダウンロードもボタン操作も発生しません。ネットワークやセキュリティ対策ソフトの都合で導入に失敗する余地をなくすための構成です。同梱せずにビルドした場合は、従来どおり GitHub の公式リリースから取得します（失敗しても既存のエンジンを壊さず、接続し直しも行います）。
- ❓ **使い方の案内** — タイトルバーの丸いボタンから開きます。基本の流れ、現在のキー割り当て、画面に重ねたものが録画へ入る条件、描き込みとレーザーポインターの使い分けをまとめています。割り当ては設定の実体をそのまま出すため、説明と手元の設定が食い違いません。
- 🔲 **範囲指定ファインダー** — 指定した領域モードでは、録画範囲を示す枠が画面に浮かびます。バーを掴んで移動、縁でリサイズでき、枠のバーからそのまま録画を開始できます。枠の内側はクリックスルーするので、録りたいアプリを操作したまま範囲を合わせられます。フルスクリーンやウィンドウのモードでは枠を描かず、操作バーだけが画面上部に残ります。既定でメインウィンドウは最小化して起動するため、どのモードでも録画・静止画・描き込みへ手が届きます。
- ⚡ **ハードウェアエンコード** — NVIDIA NVENC、Intel QuickSync、AMD AMF に対応します。搭載 GPU を起動時に検出し、使えないエンコーダは選択肢の中で理由付きで無効化します。設定されたエンコーダがその PC で使えない場合は、起動時に自動的に代替へ降格します。
- 🎚 **音声の 2 トラック分離** — システム音とマイクを別々の音声トラックとして保存します。編集ソフトで片方だけ音量を調整できます。
- ✏️ **画面への描き込み** — 録画中の画面に線・矢印・四角・文字を直接描けます。描いた内容はそのまま映像に写ります。**蛍光マーカー**は下の内容を透かす半透明の太い線で、ペンと同じく消しゴムか全消しで消すまで残ります。
- 💧 **クリックの波紋** — 録画にマウスカーソルを含める設定のとき、クリックした位置に白い輪が一度だけ広がります。カーソルが映らない録画では出しません。何も無い場所で輪が広がることになるためです。輪は録画される映像の上に出るものなので、アプリの色を持たせず白にしています。
- 🔴 **レーザーポインター** — 割り当てたボタンを押している間だけ、マウスの位置に光点が現れます。**動かした跡は押している間そのまま残る**ため、指し示した経路を 1 本の線として見せられます。中心が白く飛ぶ光点と、加算合成で重ねた 4 層の軌跡で、実際の発光に近い見え方にしています。画面を覆わないため、指し示しながら操作を続けられます。離すと形を保ったまま緩やかに薄れて消え、色・大きさ・消えるまでの時間（最長 8 秒）を設定できます。
- 🖼 **オーバーレイ** — Webカメラ、テキスト、ロゴを録画映像へ重ねられます。配置は 9 分割のアンカーと比率で持つため、録画対象の解像度を変えても画面外へ飛びません。
- 📷 **静止画キャプチャ** — PNG / JPG / BMP から形式を選べます。静止画の操作は常に 1 枚の保存です。**撮れた瞬間は操作バーの輪郭がティールに一度光り、保存したファイル名が札になって画面の隅に数秒だけ出ます**。ホットキーから撮ってもバーのボタンから撮っても同じ合図が出て、ファインダーを閉じていても札は出ます。札は録画対象と重ならない隅を選ぶため、映像には写り込みません。
- ⏱️ **定期キャプチャー** — 指定した秒数ごとに静止画を自動で保存します。［静止画］の設定で有効にし、間隔と枚数の上限（0 で無制限）を決めてから、ツールバーのタイマーボタンかホットキーで開始します。録画中でも並行して撮影でき、実行中はステータスバーに保存した枚数が出ます。1 枚の保存が終わってから次の待ち時間を数えるため、保存が長引いても撮影が積み重なりません。
- 📝 **動作ログ** — 操作の時刻とエンジンからの応答をファイルに記録します。保存するかどうかと、何日ぶんを残すかを［一般］の設定で切り替えられます。指定した日数を過ぎたものは起動時に自動で削除され、現在の保存量もその場で確認できます。映像や個人を特定する情報は記録しません。
- 🪟 **複数ウィンドウの同時録画** — ウィンドウ録画では最大 8 つまで選べます。並べ方は「画面のまま」（画面上の位置関係を保つ）・「縦に並べる」・「横に並べる」から選択でき、並べる場合はウィンドウ同士の間隔も指定できます。映像で埋まらない部分はシステム配色・ダーク・ライト・透過から選べます。出力の寸法は選んだウィンドウの実寸から決まります。タイトルが刻々と変わるウィンドウ（株価やタイマーを表示するもの、ブラウザ、編集中のファイル名を出すエディタ）も、録画のたびに現在の状態へ結び直すため見失いません。
- 📊 **リアルタイム実測値** — 実効フレームレート、ドロップフレーム数と割合、書き込み済みサイズ、CPU 使用率、保存先の空き容量を 1 秒間隔で表示します。ドロップ率が 1% を超えると警告色に切り替わります。
- 🛡 **録画の保護停止** — 指定した録画時間の上限を超えた場合と、保存先の空き容量が下限を下回った場合に、書き込み失敗を待たずに自動で停止します。
- ⌨️ **グローバルホットキー** — 録画の開始 / 停止、一時停止 / 再開、静止画の保存、定期キャプチャーの開始 / 停止、ウィンドウの表示 / 非表示、描き込みの開閉、レーザーポインターの表示をアプリ外からも操作できます。**マウスのサイドボタンや Ctrl などの修飾キー単体も割り当てられます**。欄をクリックして割り当てたい入力を押すだけで登録でき、他の操作と重複した場合はその場で警告します。
- 🪟 **ウィンドウの挙動** — 常に最前面に表示、最小化した状態で起動、Windows 起動時に自動起動、録画開始時に最小化を設定できます。

## 画面構成

Bandicam と同じ情報構造を採ります。どの設定画面を開いていても録画を開始できることを最優先し、
モードと録画操作を常時表示のツールバーへ固定しています。

```text
┌ タイトルバー ─────────────────────── エンジン状態 ─ □ × ┐
├ ツールバー ────────────────────────────────────────────┤
│ [モード ▾] [ゲーム] │ [システム音][マイク][カーソル]        │
│                    [一時停止] (REC) [静止画][定期撮影]   │
├ 情報バー：1280×720 — (320, 180), (1600, 900) ──────────┤
├────────┬───────────────────────────────────────────────┤
│ ホーム      │                                           │
│ 一般        │      選択したカテゴリの設定                │
│ ビデオ      │      （幅に余裕があれば 2 列）             │
│ オーバーレイ │      重ね合わせと描き込みの既定値          │
│ 静止画      │                                           │
│ 情報        │                                           │
├────────┴───────────────────────────────────────────────┤
│ ステータスバー：録画中は実測値、それ以外は案内            │
└────────────────────────────────────────────────────────┘
```

映像プレビューは設けません。画面録画では対象が実画面そのものであり、プレビューを出しても
自己参照になるだけで判断の役に立たないためです。録画対象の確認は情報バーが担います。

### ファインダー

ファインダーは取り込み方によって 2 つの姿を持ちます。指定した領域モードでは、録画範囲そのものを
表す透過ウィンドウが開きます。

```text
   ┌──────────────────────────────────┐ ← ファインダーウィンドウ
   │ ⠿ 1280×720        ⏸  (REC)  📷 × │  操作バー（掴んで移動）
   ├──────────────────────────────────┤
   │ ░░░░░ 掴み代 6px + 枠線 2px ░░░░░ │
   │ ░ ┌────────────────────────────┐░ │
   │ ░ │                            │░ │
   │ ░ │  録画範囲（透過・クリック  │░ │
   │ ░ │  スルー）                  │░ │
   │ ░ └────────────────────────────┘░ │
   │ ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░ │
   └──────────────────────────────────┘
```

枠線と掴み代は録画範囲の**外側**に置いています。内側に置くと枠線そのものが映像へ写り込むためです。
ウィンドウ座標と録画範囲の換算は `src/shared/types/finder.ts` の 2 つの関数だけが担い、
Main と Renderer の双方がそれを使います。ここが食い違うと、見えている枠と実際に録れる範囲がずれます。

枠を動かすと録画範囲が更新され、設定画面の数値にも反映されます。逆に設定画面で数値を変えると
枠が追従します。この 2 方向は別々の経路として実装しており、互いを呼び返さないようにしています。

フルスクリーン・ウィンドウ・ゲームのモードでは、録画範囲をこちらが決めるわけではないため枠を描きません。
主モニタ上部の中央に操作バーだけを置き、寸法の代わりに何を録っているかを表示します。

```text
⠿ 画面全体          ⏸  ● REC  📷  ✏  │  📁  🗔  ✕
```

操作バーには、録画中に必要な操作をすべて並べています。

```text
⠿ 1280×720          ⏸  ● REC  📷  ✏  │  📁  🗔  ✕
                                   │       │   │   └ 枠を閉じる
                                   │       │   └── 設定ウィンドウを表示
                                   │       └────── 保存先フォルダを開く
                                   └────────────── 画面に描き込む
```

既定でメインウィンドウは最小化して起動するため、撮影中に見えているのはこのバーだけになります。
録画・静止画・描き込み・保存先の確認まで、ここから手が届く必要があります。
システム音・マイク・マウスカーソル・Webカメラ・テキスト・ロゴの切り替えもバーに並べています。
録る直前の最終確認をここだけで済ませられるようにするためで、設定の実体は Main が持ち、
どちらの窓で切り替えても event:settingsChanged で相手側へ配られます。書き換えた本人へは
返さないので、入力中の値が往復して古い値に戻ることはありません。
範囲が狭くバーに並びきらないときは、切り替えの一群を畳んで右端の操作を守ります。

右端の赤い × はアプリごと終了します。既定でメインウィンドウは最小化して起動するため、
画面に出ているのはこのバーだけという状態が多く、そこに終わらせる手段が無いと
タスクバーからウィンドウを呼び戻すしかなくなるためです。録画中に押しても、エンジンの終了処理が
録画を先に止めてコンテナのインデックスを書かせるので、途中で切られたファイルは残りません。
枠だけを消したい場合は、設定ウィンドウのツールバーにある「範囲指定の枠」で切り替えます。

### 静止画が撮れた合図

「撮れたのかどうか分からない」を無くすため、保存の事実は Main からすべてのウィンドウへ配ります。
撮影の起点はホットキー・メインウィンドウのツールバー・ファインダーの操作バーと複数あり、
起点側の戻り値だけを見ていると、自分が押していない窓は撮れたことを知れないためです。

```text
capture:screenshot ─→ エンジンが保存 ─→ event:screenshotSaved（保存先のフルパス）
                                            ├─→ メインウィンドウ … カメラボタンの発光
                                            ├─→ ファインダーのバー … バーの発光 + ファイル名表示
                                            └─→ 札の窓 … 画面の隅にファイル名を出す
```

合図は 2 つの形で出します。バーの輪郭とカメラのボタンがティールに一度だけ光り、
あわせて保存したファイル名が現れます。光るだけでは「撮れた気がする」で終わりますが、
実際に書けたファイルの名前が出れば、撮れたことと保存先を一度に確かめられます。

明滅は繰り返さず、一度きりの減衰にしています。矩形波の点滅は安っぽく見えるうえ、
録画中に装飾アニメーションを回し続けると Renderer の負荷が乗るためです。

#### 札を独立した窓にしている理由

ファインダーを閉じ、メインウィンドウも最小化していると、合図を出す先が画面のどこにも
残りません。「撮れたのか分からない」という元の不満がそこで戻るため、どの窓の生死にも
依存しない小さな札を起動時から常駐させています。常にクリックスルーでフォーカスも奪わないため、
撮った直後にそのまま操作を続けられます。

#### 札の置き場所

札をそのまま出すと、撮れたことを知らせる札自体が録画映像へ写り込みます。避けられるかどうかは
取り込み方で変わるため、置き場所は次の順で決めます。

| 取り込み方 | 避ける相手 | 置き場所 |
| --- | --- | --- |
| 範囲指定 | 録画範囲 | 作業領域の四隅から、範囲と重ならない最初の隅 |
| ウィンドウ / ゲーム | なし | 右下。対象ウィンドウの中身だけが録られるため、別ウィンドウの札は写らない |
| 画面全体 | そのモニタ全体 | 逃げ場が無いため、録画中は札を出さない |

画面全体の取り込みでも、録画していなければ映像には残らないので普通に出します。
録画中はファインダーの操作バーが画面に残っているため、そちらの発光が合図を受け持ちます。

ファインダーの操作バーも、範囲指定以外の姿では録画対象の上に浮かびます。録画中はファイル名を
出さず発光だけに絞るのは、文字列がそのまま映像に残るためです。発光は 0.6 秒で消えるうえ、
バー自体が元から映り込んでいるので残します。

### 画面に重ねたものが録画に写る条件

描き込み・蛍光マーカー・レーザーポインター・撮れた合図の札は、すべて透過ウィンドウを画面に
重ねることで実現しています。そのため録画に写るかどうかは、取り込み方が「何を録っているか」で
決まります。

| 取り込み方 | OBS のソース | 何を録るか | 画面に重ねたものが写るか |
| --- | --- | --- | --- |
| フルスクリーン | `monitor_capture` (WGC) | モニタの合成結果 | 写る |
| 指定した領域 | `monitor_capture` (WGC) + クロップ | モニタの合成結果 | 写る |
| ウィンドウ | `window_capture` (WGC) | 対象ウィンドウ自身の描画結果 | **写らない** |
| ゲーム | `game_capture` (フック) | ゲーム自身の描画結果 | **写らない** |

ウィンドウとゲームは、対象の描画結果を直接受け取る仕組みです。画面の上に別のウィンドウを
重ねても、対象自身が描いた内容は変わらないため、映像には入りません。透過ウィンドウを重ねる
方式である限り、設定でどうにかできる性質のものではありません。録画にも残したい場合は
フルスクリーンか指定した領域で録画してください。

モード選択のツールチップと、オーバーレイのページの説明にも同じ注意を出しています。

### 画面への描き込み

透過ウィンドウに canvas で描きます。覆うのは録画される範囲だけで、指定した領域モードなら枠の内側、
それ以外なら対象モニタの全面です。範囲の外は描いても映らないうえ、覆うと操作バーへ手が届かなく
なります。描き込み窓を出したあとはファインダーを最前面へ上げ直し、操作バーが描画面の下に隠れない
ようにしています。ここを怠ると、ペンを閉じる手段が画面から消えます。

OBS のソースとして合成しないのは、描いている最中の見え方と録画結果を必ず一致させるためです。
別経路で合成すると位置や縮尺がずれる余地が生まれます。

| ツール | 内容 |
| --- | --- |
| ペン | 自由曲線 |
| 蛍光マーカー | 下の内容を透かす半透明の太い線。ペンと同じく消すまで残ります |
| 直線 / 矢印 / 四角 | 始点と終点で決まる図形 |
| 文字 | クリックした位置に入力。Enter で確定、Shift + Enter で改行 |
| 消しゴム | 触れたストロークを消します |

蛍光マーカーはペンと同系列の道具として扱い、時間で勝手に消えることはありません。一瞬だけ
指し示す用途はレーザーポインターが受け持つため、描き込み側に自動で消える仕組みを重ねると
役割が二重になり、消えてほしくない書き込みまで巻き添えで失われます。

色・太さ・蛍光マーカーの濃さは、オーバーレイのページで既定値を決められます。
描いている最中もパレットから変更できます。

### レーザーポインター

描き込みとは別の窓を使います。求められる挙動が正反対だからです。描き込みは残すために画面を
占有しますが、レーザーポインターは操作を一切妨げてはいけません。こちらの窓は常にクリックスルーで、
マウスの位置は低レベル入力フックから受け取ります。

押された瞬間に出せるよう、窓は起動時に作って隠したまま常駐させます。押している間、軌跡は
時間で消しません。指し示した経路がそのまま線として残るほうが、「ここからここへ」と辿る動きを
見せられるためです。離すと軌跡と光点の両方へ同じ不透明度を掛けて薄れさせ、形を保ったまま
消します。窓を隠すのは薄れ切ったあとで、待ち時間は設定した長さから決めます。

#### 光として見せるための描き方

区間ごとに `stroke()` を分けると、丸い線端が継ぎ目で重なって二重に合成され、点を打った位置
そのものが玉として浮き出ます。軌跡は 1 本の連続したパスとして組み、太さと濃さを変えながら
同じ形を 4 回重ねて引きます。通過点は制御点として使い、中点どうしを二次曲線で繋ぐことで、
折れ線ではなく手で振った軌跡らしい曲がりになります。

| 層 | 太さ（軌跡の基準幅に対する倍率） | 濃さ | 色 |
| --- | --- | --- | --- |
| 外側の滲み | 3.0 | 0.07 | 設定色 |
| 内側の滲み | 1.8 | 0.12 | 設定色 |
| 本体 | 1.0 | 0.45 | 設定色 |
| 芯 | 0.34 | 0.9 | 白 |

合成は加算（`lighter`）です。光が重なった所ほど明るくなる見え方を作るためで、効くのはこの
canvas の中だけです。窓そのものは透過ウィンドウとして通常どおり画面に重なるため、明るい
背景の上で白飛びすることはありません。

先端の光点は単色の丸にしません。中心を白く飛ばし、外へ向かって色を残しながら抜けていく
段階を放射グラデーションで作ります。中心が色を失って白くなるかどうかが、光として見えるか
ただの点に見えるかを分けます。

止まっている間も位置は届き続けるため、直前の点から 2px 以上動いたときだけ点を足します。
同じ場所へ重ねて足すと、加算で描くぶんそこだけ不自然に明るい塊になります。

#### クリックの波紋を同じ窓で描く理由

波紋もレーザーも「操作を妨げずに一瞬だけ示す」ものなので、面を分ける理由がありません。
分ければ透過ウィンドウが 1 枚増え、重なりの順序も管理することになります。窓の出し入れは
どちらの都合でも起きるため、隠す判断は Main の 1 か所へ集めています。押しっぱなしの間は、
波紋の待ち時間が過ぎても隠しません。

波紋を出すのは左右のクリックだけです。サイドボタンは押している間だけ働く機能の割り当て先に
なりやすく、含めるとレーザーを出すたびに波紋が重なって出ます。

#### 座標を画面基準で持つ理由

窓はカーソルのいるモニタへ追従して移ります。窓の中の座標で軌跡を溜めると、モニタを跨いだ
瞬間に原点が変わり、溜めてある点すべてがずれます。Main は画面座標とそのときの窓の左上を
一緒に送り、描くときに引きます。

割り当ては一般のページで変更でき、押している間だけ働く操作のため、既定ではマウスのサイドボタンを
使います。

## データフロー

```text
[ユーザー操作 / ホットキー]
        │
        ▼
  Renderer (React)
        │  window.capture.* （contextBridge 経由の型安全な呼び出し）
        ▼
  preload (contextBridge)
        │  ipcRenderer.invoke
        ▼
  Main : IPC ハンドラ
        │  Zod で検証 → CaptureEngine の抽象メソッドを呼ぶ
        ▼
  ObsWebSocketEngine
        │  ① 起動前: global.ini / basic.ini / recordEncoder.json を書き出し
        │  ② obs64.exe をポータブル構成で起動（空きポート + ランダムパスワード）
        │  ③ WebSocket 接続 → シーンとソースを構築 → 録画開始
        ▼
  同梱 OBS（別プロセス）
        │  グラフィックスフック / Windows Graphics Capture → NVENC 等でエンコード
        ▼
  録画ファイル（保存先フォルダ）

  ＜逆方向＞
  OBS のイベントと統計値
        │  RecordStateChanged / GetStats + GetRecordStatus を 1 秒間隔で収集
        ▼
  Main → webContents.send → preload の購読 → Zustand → UI 更新
```

エンコーダの種別だけは OBS 起動時に `basic.ini` から読まれるため、変更するとバックエンドを再起動します。フレームレート、解像度、保存先、出力形式、トラック数は WebSocket 経由でそのまま反映します。

## 付随サブシステム：キャプチャーエンジン

キャプチャーには OBS Studio のポータブル版を使います。**インストーラへ同梱し、初回起動時に
書き込みできる場所へ複製します**。ユーザーがコマンドを実行する必要はありません。

同梱する中身は、ビルドする側が `npm run engine:fetch` で用意します（`build:win` からも自動で
呼ばれます）。取得は 1 度だけで、以降は `build/engine/obs-studio/` の内容がそのまま
インストーラへ入ります。

エンジンが未配置の状態でアプリを起動すると、他の画面の代わりに準備画面が表示されます。
同梱がある場合はボタンを押す必要がなく、その場で配置が始まって録画できる状態まで進みます。
同梱せずにビルドした場合のみ、［エンジンを準備する］から GitHub の公式リリースを取得します。

導入は必ず作業用フォルダ（`<展開先>.incoming`）で組み立ててから差し替えます。途中で失敗しても、
すでに動いていたエンジンを壊しません。書き込み直後のファイルはセキュリティ対策ソフトのスキャンで
一時的に掴まれることがあるため、削除と差し替えは間隔を置いて試し直します。

```text
<展開先>/
  portable_mode.txt      … これが存在することで OBS はポータブルモードで動作します
  bin/64bit/obs64.exe    … 実行ファイル。cwd をこの階層に合わせて起動します
  data/                  … OBS 本体のデータ
  obs-plugins/           … game_capture などのプラグイン
  config/obs-studio/     … 本アプリが生成する設定。global.ini と profiles/Capture/
```

展開先は動作環境によって変わります。

| 環境 | 同梱の置き場所 | 展開先 |
| --- | --- | --- |
| 開発時 | `build/engine/obs-studio/`（Git 管理外） | `resources/obs-studio/`（Git 管理外） |
| パッケージ後 | `<インストール先>/resources/engine/obs-studio/` | `%APPDATA%/capture/engine/obs-studio/` |

パッケージ後にユーザーデータ配下へ置くのは、インストール先が `Program Files` の場合に
管理者権限なしでは書き込めないためです。

次の 3 点は構成上の必須要件です。

- **cwd を `bin/64bit` に合わせて起動すること**。OBS は `data/` と `obs-plugins/` を実行ファイルからの
  相対パスで解決するため、ここを外すとプラグインが 1 つも読み込まれず、ゲームキャプチャが候補に
  出なくなります。
- **`portable_mode.txt` を必ず置くこと**。これが無いと、お使いの PC にインストール済みの OBS の
  設定を読み書きしてしまいます。
- **アーカイブの展開時にパスを検証すること**。zip は展開先の外を指すエントリ（`../` を含む名前、
  絶対パス、外部を指すシンボリックリンク）を持ち得ます。信頼できる配布元から取得する場合でも、
  書き込み先がディレクトリの外へ出ないことは `src/main/setup/extractZip.ts` が保証します。

## 開発

### セットアップ

エクスプローラから **`セットアップ.bat`** をダブルクリックすると、依存パッケージをインストールします。
以降は **`起動.bat`** から起動できます。

```bash
npm install
```

開発中のキャプチャーエンジンは、初回起動時にアプリが配置します。同梱の中身が
`build/engine/obs-studio/` に無い場合は、`npm run engine:fetch` で先に取得してください
（約 180MB のダウンロードが発生します）。同梱が無い状態でも、アプリの準備画面から
公式リリースを取得できます。

### コマンド

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発サーバと Electron を起動します |
| `npm run typecheck` | Main / Renderer 双方の型チェックを実行します |
| `npm run build` | Main / preload / Renderer をビルドします |
| `npm run build:win` | 型チェック・エンジンの取得・ビルドの後、NSIS インストーラを生成します |
| `npm run engine:fetch` | 同梱するキャプチャーエンジンを `build/engine/` へ用意します（`--force` で取り直し） |

同じ操作を行うバッチファイルをリポジトリ直下に置いています。

| ファイル | 内容 |
| --- | --- |
| `セットアップ.bat` | 依存パッケージのインストール |
| `起動.bat` | 開発モードで起動 |
| `ビルド.bat` | 型チェック、ビルド、インストーラの生成 |

これらのバッチは、先頭で `ELECTRON_RUN_AS_NODE` を空にしています。VS Code の拡張ホスト配下の
ターミナルではこの環境変数が継承されており、そのまま起動すると Electron が素の Node として
立ち上がって `app` が undefined になるためです。

### 前提

- Windows 10 バージョン 1803 以降（Windows Graphics Capture API を利用します）
- ハードウェアエンコードを利用する場合は、対応 GPU と最新のグラフィックスドライバ
- `npm run dev` で動作することは、パッケージ後の exe で動作することを保証しません。`file://` からの起動になるため、静的資産を先頭スラッシュ付きの絶対パスで参照していないかを必ず確認してください。

### スタイルの変更について

配色、フォント、質感の単一情報源は `project_style.json` です。UI に手を入れる際は最初にこのファイルを読み、ここに定義されていない色やフォントを追加しないでください。追加が必要な場合は先に `project_style.json` を更新し、`changelogs.json` に記録してください。
